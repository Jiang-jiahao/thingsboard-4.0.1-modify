# 06-3 · 调试与排错

规则链出问题时，平台提供两层排查手段：**调试事件**（链上每个节点收到的消息与执行结果）和**节点日志**（脚本里 `console.log` / 日志节点写的内容）。

## 打开调试模式

调试模式是**逐节点开关**的，不是整条链一个总开关：

| 层级 | 开启方式 |
|---|---|
| **整条链** | 规则链列表行内没有；在**新建/编辑规则链**时的「调试模式」勾选项，或在编辑器里对每个节点单独开 |
| **单个节点** | 双击节点 → 配置面板里的**调试**一项，勾上"调试模式" |

**建议只对怀疑出问题的那几个节点开**。全线开启会让调试事件量暴涨。

## 看调试事件

打开调试模式后，让设备发一条数据，然后看事件：

| 入口 | 看什么 |
|---|---|
| 设备详情页 → **事件** 页签 | 该设备相关的全部引擎事件（含调试事件与上下线事件） |
| 规则链编辑器 → 节点上的角标 | 有调试数据时节点上会出现数量角标 |
| 实体详情页 → 事件 | 资产/设备都行 |

每条调试事件包含：

| 字段 | 说明 |
|---|---|
| **消息类型** | `POST_TELEMETRY_REQUEST` 等 |
| **发起方** | 哪个实体发来的 |
| **输入** | 该节点收到的消息体（就是脚本里的 `msg`） |
| **输出** | 该节点处理后输出的内容 |
| **错误** | 脚本抛异常时，这里会有堆栈 |

**判断方法**：

- 某个节点**没有事件** → 消息根本没走到它。往上一个节点看，是分流没接这条类型，还是过滤返回了 False。
- 有输入、**输出为空** → 节点把消息吃掉了（脚本返回了 `null`，或过滤返回 false 而 `False` 没接线）。
- **有错误** → 脚本写错了，看错误信息定位。

## 脚本里打日志

在脚本节点里用平台提供的 `console`：

```javascript
console.log('收到温度:', msg.temperature, '设备:', metadata.deviceName);
```

日志写到平台日志（容器 stdout）。系统管理员可以用 `docker logs <容器名>` 查看：

```bash
docker logs --since 5m docker-jnks-iot-rule-engine1-1 | grep -i 收到温度
```

> 规则链在 `rule-engine` 服务上执行，不在 core 上。**找日志要找 rule-engine 容器**。

## 用「日志」节点

不想写脚本时，直接在链上插一个 **日志** 节点。它把消息体写进平台日志，配置项就是一段脚本（决定打印什么）。常用写法：

```javascript
return JSON.stringify({ msg: msg, device: metadata.deviceName });
```

日志节点适合放在**每条分支的末端**，一眼就能看出消息走到了哪条分支。

## 常见故障对照表

| 现象 | 可能原因 | 怎么确认 |
|---|---|---|
| 仪表盘图表空白，但设备状态"活动" | 消息没被保存 | 在设备「事件」里看有没有 `POST_TELEMETRY_REQUEST`；再看「保存遥测数据」节点有没有输出 |
| 属性改了但没生效 | `Post attributes` 分支没接 | 看分流节点的 `Post attributes` 输出有没有连线 |
| 告警不产生 | 过滤条件不满足 / 告警节点没接 / 严重程度配错 | 调试事件看过滤节点输出的是 True 还是 False |
| 告警产生了但没人收到 | 通知规则没覆盖这种情况 | 看 [09-通知中心](../09-通知中心.md) 的「规则」页 |
| 脚本节点一直走 Failure | 脚本语法错，或引用了不存在的字段 | 看调试事件的错误字段 |
| 设备在线但上报被丢 | 设备的**设备档案**指定的规则链是空链 | 看设备档案的「详情」→ 默认规则链 |
| 消息进去了但表格里是旧值 | 保存节点写了，但仪表盘的时间窗口/聚合不对 | 见 [05-2 仪表盘编辑器](../05-仪表盘/02-仪表盘编辑器.md) |

## 排查顺序（照着走）

1. **设备侧**：设备状态是否"活动"？详情页「检查连通性」能否收到响应？
2. **入口**：设备「事件」页签里有没有 `POST_TELEMETRY_REQUEST`？没有 → 问题在设备到平台的链路上（令牌、协议、防火墙）。
3. **规则链**：打开调试模式，看消息在链上走到哪一步停住。
4. **存储**：确认「保存遥测数据」节点有输出。然后在设备「最新遥测数据」页签核对键名与值。
5. **展示**：数据在库里了，再看仪表盘的别名与数据键（[05-2](../05-仪表盘/02-仪表盘编辑器.md)）。

这五步能把"数据看不见"类问题拆成五段，逐段排除。

## 排完之后

**记得把调试模式关掉。** 调试事件会落库，长期开着会持续占用空间，也会拖慢规则引擎。
