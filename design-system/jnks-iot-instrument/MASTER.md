## 0. 方法：一律对照真实组件

**每改一屏之前，先读那一屏的真实 `.component.html` / `.scss`，再看一眼跑起来的实际页面。**
第一版的规则链、驾驶舱、设备列表都是照着"这类界面通常长什么样"画的，结果 DOM 结构和
真实组件对不上——用户的原话是「你要对照实际代码来设计，不要乱设计」。

三个具体的教训：

1. **先读 DOM 再谈视觉**。规则链真实是「左侧 260px 抽屉 + 展开面板里嵌 `fc-canvas` 预览」，
   我画成了「扁平列表 + 常驻右侧检查器」，是两回事。
2. **不要发明页面里没有的元素**。我凭想象给节点加了"输出行"和端口标签，真实节点里没有这东西。
3. **判断"用户觉得不好看"时，先找缺的是不是功能信息**。规则链那次的真因是端口和方向看不懂，
   不是配色。但如果改的方向本身是编的，改完只会更糟。

## 1. 为什么另起一套

不是因为「印与墨」不好看，而是它在**告警驱动的控制台**里有一处结构性矛盾：

**朱砂 `#c1272d` 同时是品牌强调色和危险色。**

在 ISA-101 的语境里，红色只有一个含义——异常。一旦它同时承担品牌装饰（当前项指示线、链接、页签下划线），用户在扫视屏幕时就必须先判断「这条红是装饰还是报警」。控制台的核心动作是"一眼看出哪里不对"，这个歧义正好落在最不该含糊的地方。

方向 B 的立场：**颜色全部让给语义，品牌由结构与排版承担。**

| | 印与墨 | 仪表 |
|---|---|---|
| 第一性 | 纸与印 —— 文书 | 仪与表 —— 工具 |
| 深面 | 蓝墨 `#0b1b2b`（偏蓝） | 石墨 `#14171c`（无彩） |
| 品牌强调 | 朱砂红，兼危险色 | **无彩**。唯一的彩色 `--sig` 只给焦点/链接/选中 |
| 标题字 | 宋体（衬线） | 无衬线，紧字距 |
| 圆角 | 6px | 2px |
| 主题 | 亮色为主 | **暗色优先**，亮色是派生 |
| 表格行高 | 34px | 28px |

**沿用不改的**（这些是「印与墨」已经做对的，方向 B 全部继承）：
- 正常态不上色，颜色只留给异常（ISA-101 第一条）
- 单一圆角令牌、1px 描边代替阴影、无斑马纹、无悬停上浮
- 中文走系统黑体、数据走等宽 + `tabular-nums`
- 深色侧栏 + 亮色内容区的外壳结构

### 2.2 色（只有语义，没有品牌）

| 令牌 | 暗 | 亮 | 含义 |
|---|---|---|---|
| `--sig` | `#4a9eea` | `#1f6fb8` | **功能蓝**：焦点环、链接、当前项左规、进度。占屏面积 ≤3% |
| `--ok` | `#3fb98a` | `#0f7a5a` | 运行/正常（**仅用于有明确语义的图表与状态**，列表里的"在线"仍是中性灰） |
| `--warn` | `#d9a441` | `#946a0a` | 偏高、主要告警 |
| `--crit` | `#e15b5b` | `#bf3b2e` | 严重告警、危险操作 |
| `--idle` | `#6b7684` | `#6b7684` | 停用、离线、无数据 |

> `--crit` 比印与墨的 `#c1272d` 提亮了一档 —— 深底上 `#c1272d` 的对比度不足 4.5:1。

### 2.3 字

```scss
$font-ui: "PingFang SC","Microsoft YaHei","Hiragino Sans GB","Source Han Sans SC",
          system-ui,-apple-system,"Segoe UI",Roboto,sans-serif;   // 与印与墨相同
$font-data: "SF Mono","JetBrains Mono","Roboto Mono",Menlo,Consolas,monospace;
// 没有 $font-display —— 这是相对印与墨最明显的一处减法
```

| 角色 | 字号 / 行高 / 字重 |
|---|---|
| 页标题 | 14px / 20 / 600 |
| 面板标题 | 12.5px / 18 / 600 |
| 正文、表格 | 13px / 18 / 400 |
| 表格行高 | **28px** · 表头 26px |
| 微型标签 | 10.5px / 16 / 600 · 字距 `.09em` · 全大写 |
| 数据 | 等宽 + `tabular-nums`，**右对齐** |

**微型标签是这套体系的主要识别手段**：`在线设备`、`已保存 · 2 分钟前`、`共 1,336 台` 一律走大写拉字距的小标签，与主体数据拉开层级。中文没有大小写，所以中文标签不加 `text-transform`，靠字距与颜色区分。

### 2.4 形状与密度

- `--r: 2px` · `--r-lg: 4px` · 药丸 `999px` 只给状态点
- 阴影**只给浮层**（对话框 / 菜单 / 抽屉），`--shadow: 0 10px 28px rgba(0,0,0,.55)`
- 间距基数 4px：`4 / 8 / 12 / 16 / 20 / 24 / 32`
- 过渡 `120ms cubic-bezier(.4,0,.2,1)`；不做位移、不做缩放、不做渐变

### 2.5 签名元素：刻度尺

一条 5px 高的刻线带（`repeating-linear-gradient`，每 9px 一道 1px 刻线），出现在**结构线处**：顶栏下沿、登录面板底部。它替代了印与墨里"印边"的位置——同样是一处极小的品牌标记，但取的是仪器语义。全站不超过两处。

## 3. 组件规格

**状态点**（`--ok` 不在列表里出现）
```
在线   实心 --fg-muted 圆点 + 中性文字        ← 正常态不上色
离线   空心圈（inset 0 0 0 1.5px --line-strong）+ 中性文字
主要   实心 --warn
严重   实心 --crit
```

**告警行**：左边缘 3px 色条（`inset 3px 0 0 --crit/--warn`），**级别**列写 severity，**状态**列只写确认状态。已确认不再上色——确认后告警的紧迫性已经解除，颜色留给"未确认"。

**表格**
```
表头   10.5px 大写 字距.09em --fg-faint，26px 高，无底色，下 1px --line
行     28px，下 1px --line，悬停 --bg-3
数字   .num：等宽 + tabular-nums + 右对齐
末列   ⋮ 行内动作，平时低对比，悬停才显
```

**按钮**：三档。主按钮＝反向无彩实心（暗色下白底黑字）；次按钮＝1px 描边；第三档＝无框文字按钮，仅悬停有底。**没有填充色按钮**——没有品牌色可填。

**焦点**：`1px solid --sig`，`outline-offset: 1px`。键盘可见，不用 `--crit`（红色焦点在告警语境里是误读）。

**图表**（沿用检索到的 chart 域结论）
- 1px 线，点状网格（`stroke-dasharray:"1 4"`），阈值线用 `--warn` 虚线
- 面积填充 ≤8%，不做渐变
- 区分序列用**线型 + 直接标注**，不只靠色相
- ≥1000 点切 Canvas + 降采样；实时流缓冲 60–300s
- 尊重 `prefers-reduced-motion`，静止时渲染终态快照

**规则链编辑器**（全站最复杂的一屏）

> **前提：本节所有结论来自读真实组件，不是另画一版。** 对照的文件：
> `rulechain-page.component.html` / `.scss`、`rulenode.component.html` / `.scss`、
> `rule-node-colors.scss`。原型里这一步走过弯路——第一版按"流程图"想象了一套
> 顶栏 + 常驻检查器 + 节点内输出行，全是假的，和真实 DOM 对不上。

真实结构（**原样保留，不改**）：

| 部分 | 真实实现 |
|---|---|
| 左库 | 260px 的 `mat-drawer`，**不是扁平列表**：深色渐变头 toolbar（规则链选择器）+ 白色搜索 toolbar + 一组 `mat-expansion-panel`，**每个面板里是一个 `fc-canvas` 预览** |
| 节点 | 固定 **170×50**，圆角 8，左侧图标 + 两行（`.jnks-iot-node-type` / `.jnks-iot-node-title`） |
| 引出端口 | `.fc-leftConnectors` / `.fc-rightConnectors` 挂在节点**外侧**，内含 `.fc-connector`（14px 方块）。**端口不在节点内部** |
| 连线 | `fc-canvas` 的 `curvedStyle`（贝塞尔）+ 灰箭头 + 带边框的 `.fc-edge-label` 文字标签 |
| 操作 | 右下角一排 `mat-fab`（删除 / 重置调试 / 保存 / 撤销），按脏状态启停 |
| 库折叠 | `.jnks-iot-library-node-btn`，20×90，只圆右侧 |
| 面包屑 | 来自 home 外壳，**不属于本页** |

方向 B 的改动（只有这些）：

1. **节点类型色的用法**。真实是把整块填成 `rule-node-colors.scss` 的六色调色板
   （filter `#f1e861` / enrichment `#cdf14e` / transformation `#79cef1` /
   action `#f1928f` / external `#fbc766` / flow `#d6c4f1`）。整块填充放到暗底上会变成糖果块，
   与"颜色只给语义"冲突。改成**左侧 3px 描边 + 图标取类型色**，节点面走中性石墨。
   类型照样一眼可辨，但不与告警色抢注意力。
   *六个色值不变，只换承载方式* —— 这样 `.jnks-iot-*-type` 这组类不用动。
2. **选中态**用 1px `--sig` 描边（真实是 3px `#f00` 红框）。红框在告警驱动的控制台里会被误读成报警。
   注意 `border-color` 是四边简写，选中时要显式写回 `border-left-color`，否则类型色被一起盖掉。
3. 库面板、画布底、连线、标签一律换成令牌色；`#f8fafc` / `#f9f9f9` / `#808080` / `#003a79`
   这些硬编码值全部落掉。

**不要做的事**（第一版踩过的坑）：
- 不要给节点加"输出行"或端口标签 —— 真实节点里没有这类元素，出口是靠外侧的 `fc-connector` 表达的
- 不要把连线改成正交直角 —— 真实用 `curvedStyle`，改了会和 `fc-canvas` 的绘制逻辑打架
- 不要加刻度尺、缩略图、缩放条 —— 真实没有，属于凭空发明

**首页 —— 它不是 Angular 组件**

`/home` 渲染的是**存在数据库里的仪表盘**，由 widget 组合而成（`dashboard` 表里的 JSON
+ `widget_type.descriptor`）。真实租户首页的 widget 集合与摆位：

| 行 | 部件 |
|---|---|
| 1 | 设备（非活动 / 活动 / 总数）· 告警（严重 / 分配给我 / 总数）· 开始（编号 1–6 清单） |
| 2 | 仪表盘（最近查看，空态）· 活动（时间序列，空图）· （「开始」跨两行） |
| 3 | 快速链接 · 文档 · 使用情况（实体上限进度）· 连接移动端（二维码 + 商店徽章） |

**结论：换掉 widget 组合本身是改 dashboard 定义（数据），不是改样式能覆盖的。**
本节做的只是「同一套 widget，按方向 B 重绘」。要真正重做首页内容，得单独一轮去写 dashboard 定义。

**我上一版编造的**：整屏的「KPI 条 + 遥测趋势图 + 节点负载表 + 活跃告警表」——
那是一张**全新的**仪表盘，不是对现有首页的改版。

**所以：设备列表那一屏的表格设计，等于已经把资产 / 实体视图 / 客户三页都做了。**
只有告警和配置两页因为列语义不同，才需要单独看。

## 4. 落地映射（Angular Material 18）

现有工程是 Angular Material 18（m2 API）+ Tailwind，且组件样式里有 **67 处引用 `--tb-*` 变量**。落地时：

1. **`ui/src/theme.scss`**：新增 `$jnks-iot-instrument-*` 三套调色板（primary／accent／warn），按 2.1–2.2 的色值生成 m2 palette。注意 Material 的 `primary` 会被用在**焦点环、复选框、进度条**上——按本方向这些应当是 `--sig` 而不是品牌色，所以 primary 槽直接填 `--sig` 的色阶；`warn` 槽填 `--crit` 色阶；`accent` 槽填中性灰阶。
2. **`ui/src/scss/constants.scss`**：新增方向 B 的 SCSS 变量，与现有 `$jnks-iot-*` **并存**，用 `.jnks-iot-instrument` / `.jnks-iot-instrument-dark` 两个根类切换。
3. **`ui/src/scss/ui-refinements.scss`**：把现有的 67 处 `--tb-*` 引用原样保留，**只换变量值**——这个文件已经是全局收敛层，是成本最低的落点。
4. **角标**：`--tb-radius` 从 6px 改 2px 会让全站一次性从"卡片"变"仪表"，是单点收益最大的一处改动。

## 5. 未决

- **暗色优先是否可行**：现在的部署是亮色。若选方向 B，需要确认用户群（值班室大屏 vs 办公桌面）——两者对暗色的偏好相反。
  （2026-09-21 试过整体提亮一档，用户看过认为不如原版，已回退。**不要再提亮**。）
- **无彩品牌能否接受**：方向 B 没有可填的按钮色，视觉冲击力弱于印与墨。若必须保留一处品牌色，最不容易与语义冲突的候选是**青蓝**（`--sig` 本身）而非暖色。
- **宋体的去留**：去掉宋体是方向 B 最激进的一步。若只改这一项（其余保留印与墨），会得到一个折中方案，见下方。
- 协议/术语一致性、i18n 词条、部件库描述符等**与视觉无关的历史遗留**不在本方向范围内（见 rebrand 各轮记录）。

## 6. 已知的第三种可能

如果对比后觉得"仪表太冷、印与墨太文"，折中点是：**保留印与墨的全部令牌，只做两件事**——
1. 深面从蓝墨 `#0b1b2b` 换成石墨 `#14171c`（去蓝相）
2. 朱砂从"品牌 + 危险"退成"只看危险"，品牌强调改由结构承担

这两步能单独消除第 1 节说的那个结构性矛盾，且改动量只有十几行 SCSS。**代价是失去宋体之外的差异感**——它会和方向 B 很像，但没有 B 的密度与暗色优先。

## 7. 参考稿样式：SaaS 分析风（2026-09-21 用户指定）

参考：`https://uupm.cc/demo/saas-analytics-dashboard` 的 `#dashboard` 那一段。
用户原话「我感觉这种样式挺好看的，帮我改一版这样的」。

**它是什么**：浅蓝白底（`#f5f8fd`）+ 纯白大圆角卡（14px）+ 柔和阴影
（`0 6px 24px rgba(15,23,42,.07)`）+ **浅灰填充小卡、无描边** + 蓝主色 `#2563eb`
（配紫 `#7c3aed`、绿 `#22c55e`）+ 宽松留白。KPI 是「小标签 + 大数字 + 彩色增减幅」，
图表是带透明填充的面积图 + 圆环图，进度条细而圆头。

**落地方式**：与「仪表」的**暗色**并存，**不是替换**。
原型右上角是两态分段控件：**暗黑** ⇄ **SaaS 分析风**。

> **2026-09-21 用户定稿：只要这两态。** 之前的「仪表：亮色派生」已被移除
> （用户原话「就这个 saas 分析风和暗黑可以切换这样」）。
> 亮色的令牌值仍保留在本文件第 2 节的表里，需要时可照表加回。

绝大部分改动在**令牌层**（`html[data-mode="saas"]` 一组变量），组件不动；
只有少量结构覆盖（卡片加阴影、贴片改浅底填充、次按钮改填充、导航当前项改圆角块、
登录页左面板改柔和渐变）。**这是当初把 CSS 全部走变量的回报。**

### 与「仪表」的两处根本冲突，以及本版的取舍

| 冲突 | 参考稿 | 仪表 | 本版取舍 |
|---|---|---|---|
| **颜色的用途** | 蓝/紫/绿做**装饰性**品牌色 | 颜色只给语义（ISA-101） | 品牌色收在**三处**：主按钮、当前项、图表主线。**绝不进入状态表达** —— 在线仍是中性灰，告警仍是琥珀/红 |
| **明度与密度** | 亮色优先、留白宽松 | 暗色优先、高密度 | 这版整体转亮色；但**行高与字号不动**（34px 行 / 13px 正文是实测值，改了会和真实组件打架） |

**刻意没照搬的**：参考稿的渐变标题字、玻璃拟态装饰、营销页那套彩色徽章 ——
那些是**落地页**语汇，放进控制台会变成噪音。

### 一个需要确认的点

「颜色只给语义」是前七屏一路坚持的规矩，也是方向 B 存在的**唯一理由**（第 1 节那个朱砂歧义）。
这一版为了贴近参考稿，把蓝色放进了主按钮、当前项、以及「使用情况」的进度条。
**如果蓝色继续扩散**（比如状态点、图表序列、标签底色），它就退化成又一个
"品牌色与语义色混用"的方案 —— 那正是我们一开始要解决的问题。
